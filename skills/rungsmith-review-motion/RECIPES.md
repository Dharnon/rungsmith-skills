# Review a transition under interruption

## Set up the case

Start a recording at the opener. Activate, dismiss midway and immediately select a different equipment item. Repeat with reduced motion and a slow fixture binding.

## Exercise the interaction

Check readiness of the close control, final hit area and displayed identity. A late value underneath a settled panel points to a different defect than an invisible overlay blocking input.

## Acceptance and evidence

Report one finding per observable failure, with the exact trigger sequence, resource and acceptance condition.

## Decide what deserves a finding

| Replay result | Consequence | Review disposition |
| --- | --- | --- |
| A refreshed reading replays the entire faceplate entrance | Repeated loss of context | Trace the binding or remount that restarts the entrance |
| Reversal leaves a transparent surface over the control | Input is blocked | Report the native close and hit-test sequence |
| A tab cue moves smoothly but highlights the previous asset | Wrong operational context | Fix selection ownership before tuning the transition |
| Reduced motion removes the only selected-state cue | Current selection becomes ambiguous | Specify a persistent shape, label or contrast cue |

Write the finding against the first failing resource. Include the tested client, the shortest replay and what the operator could no longer see or do. If only code is available, mark the predicted symptom and the exact native interaction needed to confirm it.

## Review an effect used on both navigation and refresh

Trigger a real navigation followed by an automatic value refresh. Record the elements that move on each. If the same class causes both movements, determine whether the user needs continuity on navigation only. Report the first wrong trigger, the correct owner and a replay that includes reduced motion plus one rapid reversal.
