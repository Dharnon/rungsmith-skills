# Translate “make it glide” into a testable request

## Set up the case

Replay the task and ask which object the operator loses: the selected row, the opening panel or the equipment reading. Identify where that object exists in the Designer tree.

## Exercise the interaction

For an expanding row, specify the persistent identity cue, the reveal target and what happens on immediate collapse. A separate popup requires a different ownership decision.

## Acceptance and evidence

Deliver the trigger, start state, destination, interruption and reduced-motion behavior in terms of actual resources.

## Disambiguate a request for a “morph”

Show the requester two fixture behaviors: a persistent equipment header with changing details, and a popup that opens independently of its trigger. Identify which relationship they need to preserve. Name the required trigger, owner and interruption behavior. State which native mechanism can express it and which geometry-dependent details still need a feasibility check.
