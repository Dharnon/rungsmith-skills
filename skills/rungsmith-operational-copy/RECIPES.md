# Write messages for states the host can distinguish

## Set up the case

List the actual triggers for request sent, accepted, confirmed, rejected and unknown. Remove any branch for which the host has no observable evidence.

## Exercise the interaction

Simulate a submitted request followed by a timeout and a later valid running indication. Read each message beside the equipment label. A timeout describes missing confirmation, not equipment failure.

## Acceptance and evidence

Record the triggering signal beside every proposed translation key and check a narrow popup in a second locale.

## Rewrite an ambiguous “Failed” message

Exercise a rejected fixture action and a timeout separately. Capture the reason each path actually provides. Write a message for each, including the asset and an available next action when the host supports one. Deliver a before/after table with the trigger, key, location and expected wording so a reviewer can verify the underlying claim.
