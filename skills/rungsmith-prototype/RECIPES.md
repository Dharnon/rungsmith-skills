# Build a native A/B switch for a maintenance task

## Set up the case

Create two development views accepting the same fixture parameters. In a separate host use a native selector bound to a local variant value. Map known variant values to the two Embedded View paths.

## Exercise the interaction

Keep equipment identity, client width and data quality fixed when switching. Use one layout that keeps history inline and one that opens details on demand. Time the task of finding the last valid measurement.

## Acceptance and evidence

Record mistaken selections and navigation steps. Keep the comparison harness outside the selected production view.

## Compare a dock with a popup

Mount the same development detail view in each host using identical params. Keep data readiness fixed. Ask the reviewer to compare the selected pump with its neighbor while details are open. Check available overview width, keyboard return and the effect of switching assets. Record which host better supports simultaneous comparison and what each costs on a narrow client.
