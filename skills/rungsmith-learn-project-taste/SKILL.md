# Learn project taste

A short, reviewable rule set grounded in the actual corrections.

## Workflow

1. Extract confirmed corrections from the session and the diff; separate user decisions from inferred reasons.

2. Turn each correction into a scoped rule with an example and rationale.

3. Propose additions or pruning to DESIGN.md; do not invent preferences or silently generalize one screen.

## Perspective constraints

Read the actual native view contract and target-version APIs. Keep process state, command permission and interlocks owned by the host. Use supported native properties/events and scoped CSS; web libraries, DOM APIs and React adapters are not executable view definitions. Preserve unrelated resources and local customizations. Do not queue per-frame Gateway scripts to imitate browser-local feedback.

## Evidence and handoff

A short, reviewable rule set grounded in the actual corrections. Record the resource paths and tested client/state. Distinguish static checks, import and native interaction verification. Mark unsupported or untested behavior explicitly.

## Example request

Review our corrections to spacing, semantic colors and disabled states. Propose reusable rules with their evidence.
