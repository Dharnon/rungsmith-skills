# Separate mounting cost from query latency

## Set up the case

Measure launch to shell and shell to first valid trend. Repeat with fixture data, then restore the history binding. Use the same host dimensions and equipment selection.

## Exercise the interaction

If fixture data removes only the second delay, inspect query execution and transforms. If mounting remains slow, compare one embedded instance with the usual repeater population.

## Acceptance and evidence

Report both timings, cold versus warm state and the single change made between runs.

## Use a counterfactual before changing a shared view

| Experiment | Hold constant | What the difference can establish |
| --- | --- | --- |
| Replace live history with a fixed result of the same size | Chart, host layout and row count | A faster first plot points to data acquisition or transformation |
| Render the same data in one instance and a full repeater | Dataset, chart settings and client | A slowdown that grows with instance count warrants inspecting per-instance work |
| Disable only the entrance transition | Query, instance count and asset | An unchanged first-data time with earlier usability points to presentation delay |

Measure the same milestone across runs. Record the spread if repeated measurements vary. If cold and warm runs disagree, publish both and explain which one represents the operator's complaint. A single screenshot cannot resolve a timing disagreement.

## Find work that continues behind a hidden tab

Compare a development host with history visible, hidden and actually absent. Use the same equipment and query interval. Observe query or binding activity alongside time to reopen the tab. Report whether the change saves work, moves latency to first use, or does both. Keep the preferred behavior tied to how operators use the screen.
